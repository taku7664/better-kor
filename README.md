# better-kor

한국어로 답하고 쓸 때 쓰는 Claude Code 스킬입니다.

번역투를 걷어내고, 억지 우리말도 억지 음차도 아닌 **그 분야에서 실제로 쓰는 말**로 전달하는 것이 목표입니다.

## 왜 만들었나

LLM이 쓰는 한국어는 대개 두 방향으로 어긋납니다.

- **억지로 우리말을 만듭니다.** 루트 노드를 "뿌리 노드", 슬라이더를 "조작 막대"라고 씁니다.
- **반대로 아무 말이나 음차합니다.** 경쟁 상태를 "레이스 컨디션", 교착 상태를 "데드락"이라고 씁니다.

판정 기준은 하나입니다. **이 판을 아는 한국 사람이 이걸 입으로 뭐라고 말하나.**

구조도 문제입니다. 결론이 맨 아래 묻히고, 확인한 것과 추측이 섞이고, 확인하지 못한 범위를 안 밝힙니다.

## 설치

```bash
git clone https://github.com/taku7664/better-kor.git
cp -r better-kor/skills/better-kor ~/.claude/skills/
```

Codex에서도 쓰려면 같은 폴더를 `~/.agents/skills/` 아래에 두면 됩니다.

## 쓰는 법

```
/better-kor            기본. 그냥 한국어를 제대로 쓴다.
/better-kor report     기본 + 자료·수치 대조 규율
/better-kor docs       기본 + 마크다운 문서 규격
/better-kor explan     기본 + 쉽게 설명
/better-kor issue      기본 + 이슈 (버그 신고·기능 제안)
/better-kor pr         기본 + PR 본문
```

**기본은 항상 적용되고 모드는 그 위에 얹힙니다.** 인자 없이 부르면 기본만 씁니다.

## 모드별로 하는 일

| 모드 | 무엇 |
|---|---|
| (기본) | 말투·상대·분량·용어·번역투. 산출물과 덧붙이는 말의 경계 |
| `report` | 전수·유일 주장의 분모 밝히기, 세는 규칙 정하기, 원문 인용 정확도 |
| `docs` | 마크다운 구조. 길게 쓰라는 뜻이 아니라 다시 찾아볼 수 있게 |
| `explan` | 비유 하나 + 그 비유가 어디서 깨지는지. 용어는 그대로 두고 한 번 푼다 |
| `issue` | 검색될 제목, 증상으로 시작, 재현 절차 |
| `pr` | 리뷰어를 읽는 사람으로. 고정 체크리스트 대신 diff에서 뽑아 쓰기 |

## 어떻게 만들었나

`report` 모드의 규율은 실제 자료를 대상으로 **6라운드를 돌리며 반례 검증에서 깨진 자리를 누적**한 것입니다. 항목마다 `(R1)~(R6)` 표시가 붙어 있어 어느 실패에서 나온 지시인지 추적됩니다.

여섯 라운드 모두 반례를 못 견뎠습니다. 깨진 자리는 라운드마다 달랐습니다.

| 라운드 | 깨진 지점 |
|---|---|
| 1 | 스스로 초안이라 밝힌 문서를 기준 삼아 다른 문서를 고치라고 함 |
| 2 | 세는 축을 하나만 돌려 보고 "어느 규칙을 써도"라고 닫음 |
| 3 | 파일 하나를 안 열어 보고 "다 봤다"고 함 |
| 4 | 같은 일을 하는 경로가 둘인데 하나만 보고 단정 |
| 5 | "전수 검색"의 분모가 전체의 일부였음 |
| 6 | 새로 주장한 개수가 실제와 어긋남 |

그 기록은 [`docs/prompt-v7-iteration-record.md`](docs/prompt-v7-iteration-record.md)에 있습니다.

번역투 임계값(몇 번 이상이면 손대나)은 직접 측정한 값이 아니라 [humanize-korean](https://github.com/jun0-ds/sonmat)의 사람 글 코퍼스 대조 결과에서 가져왔습니다.

## 아직 확인하지 못한 것

- **여섯 모드를 실제로 불러서 검증한 것은 `report` 하나뿐입니다.** 나머지는 규칙을 쓰기만 했습니다.
- 번역투 임계값이 이 스킬의 용도에 맞는지 확인하지 않았습니다.
- Codex에서 실제로 뜨는지 파일 배치만 확인했고 실행해 보지 않았습니다.
